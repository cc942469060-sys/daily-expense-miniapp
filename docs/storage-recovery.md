# 本地账本保护（v1.2.1）

本次修复针对“读取为空后静默初始化空账本”的路径。不会声称已经确认 2026-10-10 事故的最初原因，也不会自动恢复该事故中已经消失的数据。

## 读写边界

- `store.read()`、候选副本检查、诊断摘要均只读；旧格式在内存中转换，不因进入页面而写入空账本或升级结果。
- 每次读取先检查 `getStorageInfoSync()`，键存在却返回空值时按异常处理。主键缺失时还检查使用标记、快照、导入前副本、设备文件等使用证据。证据不完整或目录读取失败时，优先保留现场。
- 全新的空环境只返回用于展示的默认数据。第一次主动保存或导出 JSON 才创建主账本。
- 存在旧版账本且没有新版使用记录/文件副本时，可正常读取旧数据，首次主动保存才写入新键；旧键不删除。存在文件副本时先让用户检查，避免自动选择陈旧账本。
- 读取结果与存储对象隔离，避免平台返回对象引用时业务修改意外污染原数据。

## 保存与副本

普通修改使用同步流程：验证输入 → 重新检查主账本 → 为上一份有效 v3 建立存储与文件副本 → 写入变化的分块并逐块回读核验 → 写入主存储键中的索引并回读核验 → 更新当前版本保护并清理无人引用的分块 → 记录诊断元数据。升级前旧键本身保持完整，不在主写入前创建会妨碍升级重试的新版使用标记。

两个存储槽位 `daily-expense:snapshot:0/1` 和两个文件 `xiaorizhang-auto-0/1.json` 独立轮换。存储槽位（格式 2）保存递增序号、时间和一份账本索引，与主账本共用分块；文件（格式 1）保存递增序号、时间、完整账本、内容指纹及用于发现意外损坏的非密码学校验值，旧版本也能读取。校验还会验证账本结构、资产金额与历史一致性。轮换先选择无效或较旧槽位，另一份保持不动；导出时间变化不会淘汰不同业务数据的旧版本。

文件先写入 `.json.tmp`，回读核验后替换较旧槽位。即使替换中断，另一槽位和临时副本仍可检查。程序自动替换的只有这两个自动文件。手动导出的 JSON 只在用户于备份页确认后删除，删除接口只接受 `xiaorizhang-backup*.json` 文件名；账本读取异常时页面禁止删除，以免误删唯一的有效副本。手动 JSON 使用新名称，并检查同名冲突，避免覆盖旧备份。

设备文件写入失败时会标记是否为空间不足。主写入后的文件备份因空间不足失败，日志记为 `设备文件备份（空间不足）`，首页和备份页提示删除导出文件；下一次修改的写入前文件保护随之失败，保存被取消，并明确提示删除不需要的导出文件后重试。这里仍坚持“上一版无法保护就不改主账本”，不会自动删除任何手动导出。

主写入前保护失败会取消修改；主写入后备份失败不会谎报整次保存失败，页面显示保护不足。诊断日志写不进去时，当前会话仍保存警告状态。回读无法确认主写入结果时明确提示“勿重复提交”，由用户检查账本和副本。

## 分块存储（v1.5.0）

微信单个存储键最多 1MB、全部键合计 10MB。v1.4.4 及更早把整本账、每个存储快照和导入前副本各放在一个键里，约 4,500 笔时主账本或快照写不进去；若快照先超限，写入前保护永远失败，连删除账单也无法保存。

- 主存储键 `daily-expense:state:v3` 保存旧版单对象账本，或 `layout: "chunked"` 的索引。索引记录字段顺序、修改与备份时间、各分块的键、长度、数量和 53 位校验值，并对自身做校验。
- 分类、设置和账户资料为一个分块；账单和金额历史按原数组顺序切块，按记录 ID 的哈希决定边界（平均约 500 条，最多 2000 条或约 25 万字符）。编辑或删除只改写所在分块，追加只改写最后一块。
- 分块键 `daily-expense:chunk:*` 写入后不再修改。新内容总是写到新键并回读核验，索引最后写入，是唯一的提交点：中途失败时旧索引指向的旧分块完好；能确认索引未指向新分块时立即删除它们，否则留给下次清理。
- 存储快照和导入前副本只保存索引。保存或启动保护之后，只删除主索引、两个快照和导入前副本都不再引用的分块；任何一个索引无法解析时本次不清理。
- 写入存储因 10MB 配额用满而失败、且两个存储快照都有效时，删除序号较旧的快照并清理其独占分块后重试一次；较新的快照与两份设备文件不受影响，重试仍先完成写入前保护。文件写入失败或其他错误不触发这一步。
- 读到旧版单对象账本时照常使用，下一次主动保存时先写入快照再转换为分块；冷启动保护不改写主键。旧版本读到索引会报数据异常且不覆盖，可从格式 1 的设备自动备份文件恢复。
- 同一运行期内缓存已读取的分块和账本，读取时仍先读主键并确认所引用分块存在；分块缺失或校验失败时拒绝读取和保存。

读取不写诊断日志，以保证取证只读。持久日志由保存和启动保护流程写入，最多 40 条，仅记录时间、操作结果、运行版本和数量。诊断摘要另列当前版本、存储容量、相关键及候选状态，不含账单、金额、账户名称、卡号尾号或备注。

## 检查及恢复

入口为「我的 → 导出与备份 → 检查本地副本」。检查不修改数据，损坏主账本不妨碍导出其他有效副本。候选包括存储快照、自动文件及临时文件、旧版键、导入前副本、旧版固定名称 JSON 和新版带后缀 JSON。

恢复前显示来源、时间、账单数、账户数，并要求确认。执行前重新读取并核对副本，避免确认期间候选被轮换。已有主账本（包括损坏原文）保存到导入前副本并核验后，才写入目标；若当前完全没有账本，不用虚构空数据覆盖已有导入前副本。无法保存恢复前副本时取消操作。

恢复只代表用户选择的副本被整体替换到主账本，不代表它一定包含最新记录。应先导出需要保留的候选，再比较日期和数量。已知损坏的候选不自动使用；不自动合并不同版本。

## 日期与容量

读取历史资产时只校验日期格式及支持范围，不和当前设备日期比较；新增或更新金额仍要求不晚于今天，且不早于该账户上次金额日期。设备日期回退不会使整本数据被误判为损坏。

存储快照和导入前副本共用分块，额外占用约等于变化的分块；设备自动备份文件是两份完整账本，占用文件空间（与用户文件合计 200MB），不占 10MB 存储配额。按常见短备注约可保存 3.5 万笔，已用 80% 起提示。整体替换的恢复需要同时保留旧账本作为导入前副本，大账本之间互相恢复可能因空间不足失败，此时当前账本不变。多副本增加存储开销，满空间时会提前取消需要新保护副本的修改。手动 JSON 文件需要用户在设备外保存和管理。同一设备内的多副本不能对抗整个数据环境丢失；若存储键、文件和标记全部消失，仍需依赖外部备份。此版本没有新增云服务。

## 验收

自动测试覆盖空值/抛错、目录异常、主键缺失及旧版回退、旧格式转换、快照损坏、写入失败/静默丢写、文件替换中断、日志写入失败、恢复确认/取消及候选变化、导出冲突、隐私摘要和设备日期回退；`tests/storage-capacity.test.js` 按 1MB/10MB 限制模拟存储，覆盖超过 1MB 的账本、旧版卡在上限的账本升级、分块或索引写入失败的清理、分块损坏/缺失、顺序保持、大账本导入前副本、空间用满和容量提示；`tests/backup-cleanup.test.js` 覆盖历史导出按需检查、单个与全部删除、拒绝删除自动副本和异常账本下的删除，以及设备文件空间用满后的提示与恢复；原业务测试继续运行。另运行项目结构检查和微信 `wcc/wcsc` 编译。

发布前仍需在体验版真机验证：新增账单和账户后冷启动；导出 JSON 后再次记账；打开副本列表并导出/恢复测试副本；在独立测试账本上模拟缺失主键，确认出现异常且副本可恢复。不要在事故现场账本上做故障注入，也不要以模拟器存储代替受影响手机的数据。
