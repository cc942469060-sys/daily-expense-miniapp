# 小日账收入功能设计

设计日期：2026-10-05，业务实现：2026-10-06。本文说明收入功能的页面、数据和兼容规则，供开发与验收使用。

## 1. 目标与第一版范围

将现有个人消费账本扩展为个人收支账本。在同一套记账、明细、分类和统计页面中区分支出与收入，保留当前原生小程序、本地存储、无需登录的使用方式。

第一版包含：收入新增、编辑、删除；收入分类管理；收支筛选；收入统计；本期结余；CSV 导出和 JSON 备份兼容。

工资按实际收到的金额记录，日期使用实际到账日。未到账工资、待报销款暂不计入收入。本版暂不增加待收款管理、自动记工资、多个账户、账户余额、转账、借贷及收入退回等业务。

## 2. 记账与分类

复用 `pages/record`，顶部加入「支出｜收入」切换。普通「记一笔」入口默认支出；在收入明细中新增或使用收入入口时默认收入；编辑时读取账单本身的类型。

| 表单项目 | 支出 | 收入 |
| --- | --- | --- |
| 金额标题 | 支出金额（元） | 收入金额（元） |
| 分类 | 当前支出分类 | 当前收入分类 |
| 日期 | 支出日期 | 到账日期 |
| 方式 | 支付方式 | 收款方式 |
| 备注示例 | 午饭、买耳机 | 9 月工资、差旅报销、生日红包 |
| 保存按钮 | 保存支出 | 保存收入 |
| 累计退款 | 编辑支出时显示 | 不显示、不允许填写 |

保留现有日期、时间、备注、保存并再记一笔功能。收入的收款方式继续使用未指定、微信、支付宝、银行卡、现金、其他，不引入账户模型。

新增时切换类型，保留金额、日期、时间和备注，重新选择对应类型的分类；分类与方式的默认值取该类型最近修改的一笔，找不到则使用该类型首个分类与「未指定」。保存并再记一笔保留类型、分类和方式。

编辑时允许修正类型，但必须重新选择对应分类。已有退款的支出禁止直接转为收入，避免将退款信息静默删除；需先明确修正原退款记录。

建议默认收入分类如下，支持用户自行新增、改名、换图标：

| 分类 | 示例 |
| --- | --- |
| 工资 | 实发工资、退休金 |
| 奖金补贴 | 年终奖、绩效奖、补贴 |
| 报销 | 公司报销的差旅、采购费用 |
| 红包 | 微信红包、节日红包 |
| 礼金 | 婚礼、生日等收到的礼金 |
| 兼职副业 | 兼职工资、稿费、服务收入 |
| 投资收益 | 实际收到的利息、分红、收益 |
| 其他收入 | 其他实际收入 |

分类管理增加「支出分类｜收入分类」切换。每类至少保留一个分类，删除时只允许迁移到同类型分类。名称在同一类型内唯一，两种类型可以同名；分类 ID 在整个账本内唯一。已有分类保持名称、图标、ID 不变。

当前分类上限是全局 40 个。建议改为每种类型最多 40 个、合计最多 80 个，保证原本已有 40 个支出分类的账本也能加入默认收入分类。分类类型建立后不可直接修改，应通过新增分类和同类型迁移管理历史记录。

## 3. 首页与账单明细

首页主卡片改为本月收支概览，布局示意：

```text
本月结余                    ¥5,800.00
本月收入 ¥8,000.00     本月支出 ¥2,200.00

今日收入 ¥0.00        今日支出 ¥68.00
今天记了 3 笔

                 ＋ 记一笔

本月支出预算        还可花 ¥800.00
最近记录                         全部账单 ›
```

结余可以为负数，照常显示，例如 `−¥500.00`。收入、支出指标分别进入对应类型的明细；结余进入本月全部账单。预算使用本月净支出，收入不抵扣预算已用金额。

最近记录仍显示最近 8 笔，混合展示收入和支出。收入使用 `+¥…`，支出使用 `−¥…`，同时提供类型文字，颜色只作为辅助区分。完全退款的支出显示 `¥0.00`，仍保留支出类型和退款说明。

账单明细增加「全部｜支出｜收入」筛选，保留日期范围、分类、方式和关键词筛选：

- 全部模式：汇总显示收入、净支出、结余；分类选项注明类型，避免同名分类混淆。
- 支出模式：只显示支出分类与净支出总额；方式文案为支付方式。
- 收入模式：只显示收入分类与收入总额；方式文案为收款方式。
- 切换类型时清除不适用的分类，并重置分页。关键词搜索继续覆盖分类名和备注。
- 全部模式的每日分组显示「收入 ¥… · 支出 ¥…」；单类型模式显示对应类型小计。
- 每日小计继续按完整筛选结果计算，不能只计算已加载的 100 笔或首页 8 笔。
- 日期、分类、图表柱子等跳转到明细时必须携带收支类型；明细页不能丢失此参数。

## 4. 统计与计算口径

保留日、周、月、年及周期切换。顶部概览同时展示本期收入、净支出和结余；下方「支出｜收入」切换分别展示趋势、分类占比、大额记录和笔数。日均支出保留；收入视图可用最大单笔收入替代日均，以适应工资等低频收入。

收入趋势和支出趋势分别展示，复用现有柱状图。分类占比分别使用该类型的总额作为分母，禁止混合收支计算占比。没有该类型记录时显示零金额与对应空态。

计算规则：

```text
收入 = 所选期间、所选条件下的收入金额之和
净支出 = 所选期间、所选条件下的（支出金额 − 累计退款）之和
结余 = 收入 − 净支出
预算已用 = 本月净支出
```

收入和支出的原始金额都存为正整数「分」，收支方向由类型表达；只有计算出的结余可能为负。现有金额范围、日期范围、时间和备注校验继续适用。收入账单的退款金额固定为 0。

### 报销、退款与转账的区别

| 场景 | 记录方式 | 统计效果 |
| --- | --- | --- |
| 发工资、收红包、收礼金 | 新增收入，按到账日记录 | 增加对应期间收入 |
| 先垫付 500 元，后收到 500 元报销 | 保留 500 元支出，另记 500 元报销收入 | 同期净支出 500、收入 500、结余 0 |
| 商品退货收到退款 | 在原支出上登记累计退款 | 减少原支出日期的净支出，不增加收入 |
| 自己银行卡转钱到自己的微信 | 不作为收入或支出记录 | 不改变个人收支 |

同一笔报销若已经记为收入，就不能再作为原支出的退款，否则结余会重复增加。第一版可在报销分类说明中提示，并用备注记录对应支出；分类和备注无法可靠识别是否为同一笔款项，因此不承诺自动防重。后续可增加报销与垫付支出的关联、累计已报销及待报销金额。

当前退款没有独立到账日期，追溯扣减原消费日期。第一版继续保留该规则。因此「本期结余」是本期记账口径的收支差额，不能称为账户余额或严格现金流。比如 9 月消费在 10 月退款，9 月净支出和结余会被更新，10 月不会新增一笔收入。

若以后需要按实际资金流统计，应另外设计退款事件和退款日期；旧数据不能推断退款真正发生的日期。

## 5. 数据结构与兼容

使用同一套 `records` 和 `categories`，升级数据结构版本为 2。主要变化示例：

```js
// 分类：补充 type，保留原来的 id/name/icon/color。
{
  id: 'income_salary',
  type: 'income', // 'expense' 或 'income'
  name: '工资',
  icon: '💼',
  color: '#39775B'
}

// 账单：补充 type，金额和原字段保持兼容。
{
  id: 'bill_xxx',
  type: 'income',
  categoryId: 'income_salary',
  amountCents: 800000,
  refundCents: 0,
  payment: '银行卡', // 存储字段继续复用；界面按类型显示收款/支付方式。
  date: '2026-10-05',
  time: '09:00',
  note: '9 月工资',
  createdAt: 0,
  updatedAt: 0
}
```

校验必须保证账单类型与分类类型一致，拒绝未知类型、跨类型分类及收入带退款。版本 2 不应将缺失或非法类型默认为支出；旧数据缺失类型的兼容只发生在明确的版本 1 迁移流程。

建议核心模块新增统一收支汇总函数，返回 `incomeCents`、`expenseCents`、`balanceCents`、各类型笔数。首页、明细、分组、统计共享该结果。原有 `total()` 不能继续用于混合账单集合，否则会把工资算成消费；所有调用点必须明确口径。

升级流程：

1. 使用新主存储键 `daily-expense:state:v2`，优先读取并校验版本 2 数据；已有版本 2 数据损坏时展示恢复入口，不静默回退到旧版本。
2. 新键不存在时读取现有 `daily-expense:state:v1`；先按版本 1 规则校验，再复制迁移。
3. 所有旧账单、旧分类加上 `type: 'expense'`，保留 ID、金额、退款、日期、备注、时间戳、预算和备份时间；添加默认收入分类，生成 ID 时检查与旧分类冲突。
4. 完整校验版本 2 后写入新键，只有写入成功才完成升级；失败时保留原数据并报告失败。重复尝试不能重复插入默认分类。
5. 旧键保留为升级前副本；临近存储上限时新键写入可能失败，不通过清空原账本解决。后续可以在用户完成外部 JSON 备份后提供明确的旧副本清理入口。
6. 恢复前副本使用版本 2 独立键，不能覆盖升级前副本；旧版本有效的恢复前副本也需支持读取后迁移。

JSON 导出升级为版本 2；导入同时接受版本 1 和版本 2。版本 1 导入先校验、迁移，再展示恢复确认，未确认前不能修改当前账本。恢复仍整体替换，不做合并，并保留恢复前副本。旧版小程序无法读取新版本备份，应在说明中写清这一方向限制。

CSV 导出建议列为「日期、时间、收支类型、分类、原始金额（元）、退款金额（元）、有效金额（元）、收支方式、备注」。有效金额对收入等于收入原始金额，对支出等于净支出，保持非负，由类型表示方向；收入退款列留空。保留 UTF-8 BOM、逗号/引号/换行转义和公式前缀保护。CSV 仍仅用于阅读，不用于恢复。

## 6. 实现顺序与验收

建议分三步开发，每一步保持旧功能可用：

1. 核心金额/统计、类型校验、版本迁移与备份兼容。
2. 记账页、分类管理、共享账单列表与明细筛选。
3. 首页与统计展示、导出、页面文案、README 和真机验收。

| 文件/目录 | 主要变更 |
| --- | --- |
| `miniprogram/utils/core.js` | 类型、默认收入分类、校验、筛选、汇总、分组、统计、CSV |
| `miniprogram/utils/store.js` | 版本迁移、分类隔离、保存收入、备份导入与恢复前副本 |
| `miniprogram/utils/ui.js` | 新增记账入口携带类型 |
| `miniprogram/pages/record/` | 类型切换、收入表单文案、支出专属退款 |
| `miniprogram/pages/categories/` | 分类型管理、同类型迁移、分类型数量限制 |
| `miniprogram/components/bill-list/` | 收支方向、类型、每日分项汇总 |
| `miniprogram/pages/bills/` | 收支筛选、分项汇总、类型参数与分页 |
| `miniprogram/pages/home/` | 本月与今日收支、结余、支出预算 |
| `miniprogram/pages/stats/` | 分类型趋势、分类占比、排行、钻取 |
| `miniprogram/pages/mine/`、`pages/backup/`、`README.md` | 分类数、备份版本说明、收支文案 |
| `tests/core.test.js`、`store.test.js`、`pages.test.js` | 收支计算、迁移和页面流程回归 |

关键验收：

- 同期收入 8,000 元、支出 2,200 元，首页、统计、筛选明细结余均为 5,800 元；收入不能减少预算用量。
- 500 元垫付支出加 500 元报销收入，收入、支出各 500 元，结余为 0；退款单独按原规则验证。
- 纯收入、纯支出、空账本、支出超过收入、完全退款均能正确显示；分类占比分母与所选类型一致。
- 同一日超过 100 笔混合收支，首页最近 8 笔和明细第一页的日期汇总均包含完整筛选结果。
- 切换类型不会把收入分类带到支出；收入编辑没有退款输入；趋势和分类点击只显示对应类型明细。
- 旧账本及旧 JSON 导入后，原支出统计和预算完全一致；满 40 个旧分类也可迁移；重复读取不重复添加分类。
- 新 JSON 往返保留收支、分类、预算、退款；旧恢复前副本可迁移恢复；迁移、保存或恢复写入失败时原账本仍保留。
- CSV 包含收支类型，中文、特殊字符与公式前缀保护继续正确；使用开发检查、模拟器和真机验证最终实现。
