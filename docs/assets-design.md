# 小日账资产与负债功能设计

设计日期：2026-10-08。用户已选择：先手动更新余额或市值，快速查看全部资产和负债。第一版已在 v1.2.0 实现；金额历史按每页 50 条浏览，分类构成占比放在对应分类分组内。

## 1. 目标与范围

底部导航调整为「首页｜统计｜资产｜我的」。资产页回答三个问题：目前记录了多少资产、还有多少负债、净资产是多少。

第一版采用人民币手动盘点：用户录入各项资产当前余额或估值、各项负债当前未还金额，系统汇总并展示构成。每个账户保留金额更新记录，支持新增、改名、更新金额、归档和备份。

收支账单仍描述某段时间的收入与支出；资产账户描述某个日期的余额或估值。第一版二者独立，记收入、支出、退款不会自动增减资产金额。首页「本月结余」与资产页「净资产」分别展示，不能互相替代。

第一版不接入银行、支付宝、微信或证券账户，不自动抓取余额、股价或金价；不要求提供账号密码。股票、黄金等先填写整体估值，不做交易、持仓成本或盈亏核算。

## 2. 资产分类与账户

分类表达资产形式；账户表达具体持有项目。同一分类可以建立多个账户，例如「招商银行·工资卡 1234」「工商银行·储蓄卡 5678」。平台名称可以写在账户名中。

| 资产分类 | 账户示例 | 填写金额 |
| --- | --- | --- |
| 银行卡 | 招商银行·工资卡 | 当前卡内余额，已单独建账的理财不重复计入 |
| 支付宝 | 支付宝余额 | 支付宝余额；余额宝可在基金/理财下单列 |
| 微信 | 微信零钱 | 微信零钱；零钱通可在基金/理财下单列 |
| 股票 | 某证券·股票市值 | 手动填写当前股票总市值；券商现金单列时不包含在内 |
| 国债 | 某期储蓄国债 | 当前持有金额，暂不自动预计未来利息 |
| 黄金 | 金条、黄金积存 | 手动填写当前估值，备注可记录克数和估值依据 |
| 基金/理财 | 余额宝、零钱通、银行理财 | 当前产品金额或估值 |
| 现金 | 备用现金 | 当前持有现金 |
| 其他资产 | 券商可用资金、借出待收款、房产等 | 用户确认的当前金额或估值 |

保留「其他资产」与自定义分类入口，以覆盖用户自己的资产形式。资产分类独立于现有收支分类管理；支出中的「理财」「贷款」「保险」不是资产账户。

同一笔钱只计一次。例如已经分别录入支付宝余额和余额宝，就不再额外添加包含两者的「支付宝总资产」账户。股票可以选择按证券账户汇总，也可以逐只建账，但同一组持仓不能同时录入汇总和明细金额。

## 3. 负债分类与账户

| 负债分类 | 账户示例 | 填写金额 |
| --- | --- | --- |
| 信用卡 | 招商信用卡·待还 | 当前欠款，包括已出账和未出账的未还部分 |
| 房贷 | 住房贷款 | 当前剩余未还金额 |
| 车贷 | 汽车贷款 | 当前剩余未还金额 |
| 消费贷/分期 | 花呗、白条、消费贷款 | 当前欠款，避免与单独记录的分期重复 |
| 个人借款 | 向家人借款 | 当前尚未偿还的金额 |
| 其他负债 | 其他应付款 | 当前尚未偿还的金额 |

用户填写「当前欠款」，统一输入正数或零，由账户类型决定其属于负债。信用额度、已还金额、未来尚未发生的利息不作为当前欠款录入。信用卡如有溢缴款，可单独记为其他资产，第一版不使用负数负债表示。

负债不会与银行卡存款相互抵消后再入账。例：银行卡有 5 万、贷款剩余 3 万，应分别记录资产 5 万、负债 3 万，净资产为 2 万。

```text
我的资产                         显示/隐藏金额

净资产                          ¥100,000.00
总资产 ¥160,000.00         总负债 ¥60,000.00
按各账户最近一次更新金额汇总

                 ＋ 添加账户

全部                 资产                 负债
全部分类 ▾                 分类管理 / 已归档

银行卡                            ¥58,000.00
  招商银行·工资卡 1234             ¥58,000.00
  金额日期：2026-10-08                 更新 ›

支付宝                             ¥3,000.00
  支付宝余额                        ¥3,000.00
  金额日期：2026-10-08                 更新 ›

股票                              ¥40,000.00
  某证券·股票市值                   ¥40,000.00
  金额日期：2026-10-08                 更新 ›

资产构成

首页             统计             资产             我的
```

布局中的金额只是示例，不会写入真实账本。首屏先给出净资产、总资产、总负债三个数字，再展示账户；沿用目前浅色背景、绿色主卡片和大按钮风格。

- 点击「总资产」或「总负债」切换对应账户列表，汇总数字始终覆盖所有有效账户，不受列表分类筛选影响；筛选后的列表另显示该分类小计。
- 资产与负债分别展示分类小计和构成占比，分母分别为总资产、总负债。金额为零时显示空态，不计算无意义的百分比。
- 「显示/隐藏金额」同时作用于顶部、账户列表、分类小计、占比及金额更新记录，保存本机偏好。
- 每个账户显示金额日期；总览说明各账户可能不是同一天更新。超过 30 天未更新可显示「较久未更新」，只作页面提示，不自动修改金额。
- 没有账户时显示「添加第一个资产或负债账户」，不能用收入总额或已有收支结余填充资产。
- 非零负债使用独立文字与颜色识别；净资产允许为负，不把负数截成零。

第一版以当前总额、分类构成和账户更新记录为主。净资产趋势建议后续基于主动保存的完整盘点记录增加，避免把逐个添加初始账户造成的跳变误认为资产增长。

## 5. 添加与维护账户

添加页面顶部选择「资产｜负债」，表单如下：

| 字段 | 规则 |
| --- | --- |
| 分类 | 必填，只显示对应资产或负债分类 |
| 账户名称 | 必填，建议 1—24 字，例如「招商银行·工资卡」 |
| 当前余额/当前市值/当前欠款 | 必填，允许 0，最多两位小数；标题按分类调整 |
| 金额日期 | 默认今天，不得晚于今天 |
| 卡号后四位 | 银行卡/信用卡可选，用于区分账户；不要求完整卡号 |
| 备注 | 可选，例如用途、产品到期日、黄金克数或估值说明 |

股票和黄金的金额标题为「当前市值/估值」；负债统一为「当前欠款」。第一版不依据数量、单价或利率自动计算，避免填写一个信息就误认为已经获得实时价格。

账户详情展示金额、金额日期、分类、备注，以及最近金额更新记录。主要操作为「更新金额」，次要操作为编辑账户信息和归档。

更新时输入新的完整金额，不输入差额。例如余额从 10,000 变成 9,200，填 9,200；系统保存旧值、新值、差额和日期。更新相同金额也可以，用于确认盘点日期。新金额日期不得早于该账户当前金额日期；历史日期修订不在第一版范围内。

差额只称「金额变动」，不称「收益」或「盈亏」：金额变化可能来自消费、转账、追加资金、还款或市场估值。更新金额不会创建收支账单。

账户资产/负债属性建立后不可直接切换；更换分类只能选择同一属性的分类。删除自定义分类时，已有账户迁移到同属性分类，账户金额不变。

金额为零的账户允许归档，保留其更新历史；非零账户需先确认实际余额并更新为零，或继续保留。归档账户在单独列表可查看和重新启用，不计入当前有效账户数量。只有无后续更新历史的误建账户才提供明确确认的删除操作，不能通过删除普通账户静默抹掉历史。

## 6. 汇总与收支边界

```text
总资产 = 所有未归档资产账户当前金额之和
总负债 = 所有未归档负债账户当前欠款之和
净资产 = 总资产 − 总负债
资产分类占比 = 该资产分类金额 ÷ 总资产
负债分类占比 = 该负债分类金额 ÷ 总负债
```

所有账户录入金额以非负整数「分」保存，只有净资产和更新差额可以为负。初始余额是盘点起点，不生成收入；初始负债不生成支出。

手动模式的典型操作：

| 情况 | 收支账本 | 资产页 |
| --- | --- | --- |
| 收到工资 | 记工资收入 | 按实际银行卡余额手动更新 |
| 日常消费 | 记对应支出 | 需要盘点时更新支付账户余额 |
| 银行卡转入微信 | 无需新增收入/支出 | 分别更新两个账户，资产总额不应因转账本身变化 |
| 股票或黄金估值变化 | 不自动生成收入/支出 | 更新当前估值，记录金额变动 |
| 归还贷款 | 延续用户现有记账方式 | 分别更新付款账户与剩余欠款 |
| 收到退款 | 原支出填写累计退款 | 按实际账户余额手动更新 |

现有「支付方式」仅是微信、支付宝、银行卡等标签，不能定位某一张卡；已有退款也没有独立到账日期。因此第一版不从历史账单反推账户余额，不根据「理财」「贷款」分类自动生成资产或负债。

以后若接入自动联动，需要再设计具体账户关联、期初余额、转账、投资申购赎回、借款、还本付息、信用卡消费与还款，以及退款到账事件。届时必须区分本金变动和费用，避免重复计支出；旧账单保留原统计口径，不能无提示地重算。

## 7. 数据与兼容设计

建议把账本结构从版本 2 升级为版本 3，新增独立资产字段，继续使用一次性写入整个主账本的方式，避免账户金额已保存而历史记录未保存。

```js
{
  version: 3,
  records: [],           // 现有收支账单
  categories: [],        // 现有收支分类
  settings: {},          // 保留预算和支出分类升级标记，新增金额隐藏偏好
  assetCategories: [
    { id: 'asset_bank', kind: 'asset', name: '银行卡', icon: '🏦' },
    { id: 'debt_credit', kind: 'liability', name: '信用卡', icon: '💳' }
  ],
  accounts: [
    {
      id: 'account_xxx', kind: 'asset', categoryId: 'asset_bank',
      name: '招商银行·工资卡', amountCents: 5800000,
      valuedOn: '2026-10-08', cardLast4: '1234', note: '',
      archivedAt: null, createdAt: 0, updatedAt: 0
    }
  ],
  accountValueHistory: [
    {
      id: 'value_xxx', accountId: 'account_xxx',
      previousCents: null, amountCents: 5800000,
      valuedOn: '2026-10-08', recordedAt: 0,
      reason: 'opening' // opening 或 manual_update
    }
  ]
}
```

`accounts.amountCents` 与金额历史在同一次保存中更新；普通信息编辑不追加金额变动。首条记录使用空的 previousCents，界面显示「初始录入」，不显示为赚到一笔钱。

金额校验应独立于现有单笔收支上限：资产账户建议支持 0—999,999,999.99 元，最多 200 个账户，汇总仍在 JavaScript 安全整数范围内。资产/负债分类各最多 40 个，金额历史建议最多 20,000 条；写入前检查容量和结构，超限时明确报错，不自动丢弃历史。这些是应用校验限制，不承诺设备一定能容纳上限数据。

升级与备份规则：

1. 新主存储键使用版本 3，优先读取新数据；新键不存在时逐级读取版本 2/1 并迁移。已有新数据损坏时不回退到陈旧副本。
2. 保留旧收支记录、分类、预算、分类补齐标记和原时间信息；初始化资产分类，账户和金额历史为空。首次进入由用户添加实际资产。
3. 完整校验后写入新键，成功后才视为升级完成；写入失败保留旧数据。升级前副本与恢复前副本分开保存。
4. JSON 导出版本 3，包含账户、资产分类、金额历史和全部收支数据；导入支持版本 1/2/3。
5. 旧版本备份没有资产。恢复确认明确展示收支笔数、资产账户数、负债账户数，并说明整体替换会一并替换当前资产数据；确认前不改当前数据，恢复前保留副本。
6. 现有账单 CSV 保持收支含义，另外增加「导出资产清单」，列出属性、分类、账户名称、当前金额、金额日期、状态和备注。
7. 校验账户属性与分类一致、ID 唯一、金额与日期有效、历史引用存在、历史与当前值一致。归档账户和历史也进入 JSON 备份。

## 8. 实施顺序与验收

建议先完成数据模型和迁移，再完成账户增改与金额记录，最后接入底部导航、汇总与分类构成、导出备份。现有底部菜单由 app.json 配置；资产业务可集中放入新的 assets 工具模块，减少现有收支计算逻辑的改动。

| 文件/目录 | 计划职责 |
| --- | --- |
| `miniprogram/app.json`、`assets/`、`scripts/icons.js` | 增加资产菜单与正常/选中图标 |
| `miniprogram/pages/assets/` | 净资产总览、资产/负债切换、分组和构成 |
| `miniprogram/pages/account/` | 添加、详情、金额更新和历史 |
| `miniprogram/pages/asset-categories/` | 独立资产/负债分类管理 |
| `miniprogram/utils/assets.js` | 金额、账户、盘点历史及汇总规则 |
| `miniprogram/utils/core.js`、`store.js` | 版本 3 校验、迁移、保存与恢复 |
| `miniprogram/pages/backup/` | 资产清单 CSV、新版 JSON、恢复确认 |
| `tests/`、`README.md` | 业务回归和使用说明 |

主要验收场景：

- 资产 160,000 元、负债 60,000 元，净资产应为 100,000 元；负债超过资产时显示负净资产。
- 一张卡从 10,000 更新为 9,200，资产减少 800，历史记录差额为 −800，收支统计和预算不变。
- 收到工资并记收入后，资产值不自动变化；手动更新资产后不会再生成第二笔收入。
- 同名的资产、负债或收支分类互不混淆；列表分类筛选不会把总资产卡片变成局部合计。
- 初始余额、零金额、只有负债、空账本、不同更新日期、金额隐藏和归档恢复都能正常展示。
- 同名账户可以用后四位或名称区分；不会按名称合并两张银行卡。
- 保存金额失败时当前金额和历史都不变；编辑普通信息不会产生金额变动记录。
- 版本 1/2 数据升级后原收支统计完全一致；版本 3 JSON 往返后资产、负债、历史及偏好完整。
- 导入无资产的旧备份时明确提示整体替换，取消后资产保持原样。

第一版推荐交付范围：资产菜单、净资产总览、资产/负债分类、账户增改与归档、手动金额更新记录、金额隐藏、资产清单导出和完整备份兼容。
