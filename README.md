# 小日账 · 微信个人收支账本

原生微信小程序 v1.5.0，JavaScript + WXML + WXSS，无第三方运行依赖、无需服务器、无需登录。首次浏览仅显示空账本，不写入存储；首次主动保存或导出 JSON 时创建账本。

## 如何运行

1. 打开微信开发者工具，选择「导入项目」。
2. 导入整个 `daily-expense-miniapp` 文件夹，也就是包含 `project.config.json` 的目录；不要单独导入 `miniprogram`。`miniprogram/` 里另有一份 `project.config.json`，只在单独导入该目录时生效，按本步骤导入时不使用。
3. `project.config.json` 当前填写的 AppID 为 `wx422617780bbbaa86`。没有这个小程序的开发权限时，把其中的 `appid` 改成自己的小程序 AppID；仅做本地调试也可在工具支持时改用测试号/游客模式。真机预览、上传和发布必须使用自己有权限的 AppID。
4. 后端服务选择「不使用云服务」，点击编译。无需 npm install，也无需构建 npm。
5. 正式发布前，在微信公众平台完善名称、类目等资料，使用真实 AppID 预览并完成真机验收后，再按平台流程提交审核。

项目没有联网请求，不需要配置业务服务器域名。Node.js 仅用于运行开发检查和测试，不是小程序运行条件。

## 已实现的功能

- 首页：本月收入、净支出与结余，今日收支和笔数，支出预算进度、近 30 天记录（含今天及此前 29 个自然日）。收支按时间从近到远展示，每次加载 100 笔，可继续加载该范围内全部记录，加载更多只追加新的一页；日期小计始终包含当天全部收支。返回首页时刷新日期范围，更早的记录通过「全部账单」查看。 超过 30 天没有发送 JSON 备份时（从未发送则从第一笔记录算起），首页提醒去备份，可选择 7 天后再提醒；「我的」页显示上次发送备份的时间。
- 快速记账：分类按近 90 天的使用次数排序，常用的排在前面（分类管理中的顺序不变）；支出/收入切换，金额、对应分类、日期、时间、支付/收款方式、备注；支持补记、保存后继续记账。默认收入分类包括工资、奖金补贴、报销、红包、礼金、兼职副业、投资收益、其他收入。
- 账单详情：编辑、删除确认；支出支持累计退款登记，收入不能登记退款。修正收支类型时须重新选择分类，已有退款的支出需先修正并保存退款。
- 统计：日、周、月、年、全部、自定义切换；支持跨年起止日期，例如 2024-01-01 至 2026-10-11；本期收支与结余，按收入/支出查看总金额和笔数；支出显示日均，收入显示最大单笔。
- 收支趋势：收入和支出分别展示，周/月按日、年按月展示柱状图；全部和自定义根据跨度按日、月或年汇总，点击柱子先显示该区间及金额，再次点击或点说明进入对应范围、对应类型的明细。
- 分类统计：金额、百分比、进度条，收入和支出各自计算占比；点击分类查看本期对应类型明细；显示本期大额收支。
- 账单明细：全部/支出/收入、日期范围、分类、收支方式、备注/分类关键词筛选；支持时间从近到远、金额从大到小、金额从小到大排序。时间排序按日期分组汇总，金额排序跨日期展示并逐笔标注日期；先排序全部筛选结果，再按 100 笔分页加载；滑到底部自动加载下一页，只传输新加载的部分。
- 分类管理：收入、支出分别新增、改名、换图标；删除分类时把历史账单迁移到同类型分类。每种类型至少保留一个分类，同类型内名称唯一。
- 支出预设：餐饮、交通、购物、住房、娱乐、医疗、学习、其他，以及保险、理财、贷款、旅行、长辈、礼金。支出礼金与收入礼金分别统计。
- 月预算：可设置金额，填 0 或留空关闭。
- 资产：底部「首页 / 统计 / 资产 / 我的」，展示总资产、总负债、净资产，以及资产和负债各自的分类占比。
- 账户：银行卡、支付宝、微信、股票、国债、黄金、基金/理财、现金、其他资产；负债包括信用卡、房贷、车贷、消费贷/分期、个人借款、其他负债。支持多个同类账户、手动金额更新历史、零余额归档与重新启用、独立分类管理、金额隐藏。
- CSV：导出全部账单，支持 Excel 阅读中文；正确转义引号、逗号和换行，处理公式前缀。
- JSON：备份/恢复全部账单、账户、金额更新历史、分类和设置；格式校验、替换前确认、保留恢复前副本。另可导出独立的 CSV 资产清单。

## 资产使用规则

1. 在「资产」添加账户，选择资产或负债、分类，填写名称、当前金额及金额日期。尾号和备注选填，同名账户可并存。
2. 所有金额均为人民币。银行卡、钱包填余额；股票、国债、黄金、基金等填手动核对的当前市值或估值；负债填当前未还金额（正数）。单账户支持 0—999,999,999.99 元。
3. 总资产、总负债汇总所有使用中账户，净资产 = 总资产 − 总负债，可为负数。列表筛选不改变顶部全局合计；归档账户金额必须为零。
4. 通过「更新当前金额」填写完整新金额，日期不早于上次金额日期、不晚于今天。可填写相同金额以更新核对日期。系统原子保存新金额与更新历史，失败则两者都不改变；超过 30 天未更新的账户显示提示。
5. 修改名称、分类、尾号或备注不产生金额更新记录。归档保留全部历史，可重新启用；仅尚未更新过金额的误建账户可确认删除。
6. 收入、支出、退款与账户余额独立，互不自动调整。转账后可分别更新两边余额；钱包内已单列的理财不要重复登记。金额变动不直接当作收益或收支。
7. 隐藏金额覆盖合计、分类金额与占比、账户列表、详情及金额历史；设置在重启后保留。点击「显示并更新金额」会显示可编辑的当前金额。导出的 CSV/JSON 仍保留真实金额。
8. 资产和负债分类各自新增、改名、更换图标；删除时只能迁移到相同类型分类，归档账户也会迁移。每类至少保留 1 个、最多 40 个分类。
9. 本版不接行情、不计算持仓收益或自动利息、不做借贷还款计划和净资产趋势。设计细节见 [资产设计](docs/assets-design.md)。

## 统计规则

1. 金额存为整数「分」，展示为人民币「元」。单笔金额为 0.01—9,999,999.99 元，最多两位小数。 页面显示金额带千分位（如 ¥5,800.00），输入框和 CSV 导出仍为不带分隔符的数字。输入金额时可写成 12. 或 .5，也可粘贴正确分组的千分位金额（如 1,234.50）；12,34 这类含糊写法会被拒绝。
2. 净支出 = 原支出 − 累计退款，结余 = 收入 − 净支出。退款继续扣减原支出日期的统计；本期结余是记账口径的收支差额，不是账户余额或按退款实际到账日计算的现金流。
3. 周从周一到周日；月和年使用自然月、自然年，支持闰年及跨年周。
4. 支出的当前周期日均按已过自然日计算，历史周期按全部自然日计算，包括无支出的日期。收入视图显示最大单笔收入。
5. 日期分组小计按当天的完整筛选结果计算，即便列表尚未加载完，也不会少算金额。
6. 完全退款的记录仍计入支出笔数，仍可从明细查询，支出分类占比按净支出计算；收入分类占比只使用收入总额。
7. 记账日期范围为 2000 年起至今天，不支持未来记录。默认分类及收付款方式参考相同收支类型下最近修改过的记录。
8. 月预算设置对所有月份采用同一金额，预算已用只计算净支出，收入不抵扣预算用量，暂不提供每月独立预算历史。
9. 收入按实际到账日期和实收金额记录，待发工资、待报销款暂不计入。报销作为收入时保留原垫付支出，不再把同笔款项登记为退款。例如同期垫付 500 元、报销到账 500 元，结余为 0。当前通过提示和备注区分，不自动关联或去重。
10. 自己账户之间转账不记收入或支出；收入中的投资收益分类记录实际收到的收益，不把本金转入或赎回当作收入。
11. 「全部」从首笔账单起统计至今天；设备日期回退时也包含已保存的较晚账单。空账本使用今天。收入和支出共用同一日期范围。「自定义」可选择 2000 年起至今天的任意起止日期，包含首尾当天，切换收入/支出或其他统计模式后仍保留本次选择。
12. 全部和自定义范围不超过 62 天时按日汇总；超过 62 天、涵盖不超过 24 个自然月时按月汇总；更长范围按年汇总。首尾柱子的明细范围裁剪到所选日期，合计、分类、趋势和明细使用同一范围。日均包含所选范围内没有支出的自然日，不按有账单的天数计算。统计筛选只影响显示，不修改账本数据。

账单明细中的「排序」默认按时间从近到远。从统计分类进入后切换金额排序，会保留日期、收支类型、分类等筛选条件。支出按扣除退款后的显示金额排序，收入按实收金额排序；混合视图按金额大小比较，收入和支出仍分别显示正负号，金额相同按时间从近到远。切换筛选、加载更多和编辑返回后保留当前排序；「重置」恢复时间排序。排序不修改账单、统计合计或导出顺序，新开明细页仍默认时间排序。

## 导出和恢复

备份页默认只显示「JSON 完整备份」「最近一次手动备份」和「从聊天文件恢复」；历史导出、CSV、高级恢复与诊断收在「更多选项」中，账本读取异常或保护不足时自动展开。页面默认只展示最近一次手动生成的 JSON 备份，按文件名中记录的生成时间排序（不按账单更新时间排序；旧版固定文件名排在最后）。其他手动备份归入“历史导出”，自动快照、设备备份及导入/升级前副本归入“高级恢复”，两组默认折叠。展开和收起只影响显示，不删除文件；历史导出折叠时只列出文件名和大小，展开时才读取检查，避免文件多时页面变慢。页面显示手动导出共占用的空间，时间均按本机时区显示。已有导出可直接发送原文件，不再另建副本。重新进入页面会重新发现最新备份；未记录单个文件的发送结果时明确显示“发送状态未记录”，不会把文件存在误认为已发送。

生成文件和发送分为两步：点击生成后，页面显示“发送／重试发送”，再次点击才调用微信发送接口。JSON、CSV 和本地副本均使用此流程；重试使用同一文件，取消或失败不更新备份成功时间。同一文件可以多次发送，每次成功都会更新备份成功时间；记录发送时间不算修改账本，副本列表里的「账本时间」不会因此改变。发送前同步检查文件存在且非空，失败在页面显示实际错误并纳入本次会话的诊断摘要（本地文件路径脱敏）。退出页面后可在本地副本列表重新导出 JSON。生成后账本已有变化时，发送旧文件不会将当前账本标记为已备份。

「我的 → 导出与备份」：

- **CSV**：分别导出账单或资产清单（含归档账户），用于 Excel 阅读；资产 CSV 包含当前金额但不包含金额更新历史，不能从 CSV 恢复。
- **JSON**：发送并保存版本 3 的完整备份，包含收支和资产数据；新备份需在支持资产的版本中恢复。请在设备之外保存文件；只生成设备内文件不等于完成外部备份。
- **恢复**：支持版本 1 的旧支出备份、版本 2 的收支备份和版本 3 的资产备份。确认后整体替换全部数据，不做合并。旧版备份没有资产账户，确认框会明确提示当前资产也将清空；取消不会修改账本。
- **恢复导入前副本**：可返回最近一次导入前的账单、资产、历史、分类和设置。导入后新增或修改的数据不会包含在该副本中，操作前会确认。恢复没有完成时，当前账本和导入前副本都保持不变，可以重试。

CSV 使用固定文件名 `xiaorizhang-bills.csv` 和 `xiaorizhang-assets.csv`。JSON 每次生成带时间和唯一后缀的新文件，不覆盖以前的备份；同名冲突会取消导出。历史 JSON 会占用空间，请在设备之外妥善保存；程序不会自动删除手动导出的文件。可在「历史导出」中删除单个文件，或一次删除全部历史导出（保留最近一次手动备份）；删除需确认、无法恢复，不影响已发送到聊天的文件。账本读取异常时不允许删除，以免误删唯一的有效副本。

「检查本地副本」会只读列出历史快照、设备自动备份、升级前账本、导入前副本和曾导出的 JSON 文件，显示账本时间、账单数及账户数。可先单独导出候选副本，再确认恢复；发现副本已变化时会要求重新检查。即使主账本损坏，也可以检查和导出有效副本。主账本还在但读出来是空的时，恢复前会说明情况并再确认一次。「复制诊断摘要」只包含版本、数量、时间及操作状态，不包含金额和账单内容。

开发者工具的文件选择/发送能力可能受环境限制，JSON 文件导入和发送需要真机验收。取消发送不会更新「最近成功发送备份」时间。这个时间表示微信文件发送 API 返回成功，不表示文件已永久保存。

## 旧版本升级

v1.5.0 解除微信单个存储键 1MB 造成的约 4,500 笔上限：账单和金额历史改为分块保存，每块远小于 1MB，主存储键只保存很小的索引。v1.4.4 及更早写入的单键账本照常读取，下一次主动保存时自动转为分块格式，无需重新导入；转换前会先把原账本写入快照。已经因为接近上限而无法新增或删除的账本，升级后可以继续使用。JSON 备份格式不变。若回退到旧版本，旧版本读到分块索引会提示数据异常且不覆盖，可在「高级恢复」中从设备自动备份文件恢复。同时修复：保存过程中重复点击「保存」可能记两笔并多返回一页；备份页的生成时间和账本时间按 UTC 原文显示；「我的」页版本号未随版本更新。保存时只处理有变化的分块，3 万笔账本在无 JIT 的环境下保存一笔从约 0.8 秒降到约 0.13 秒，冷启动从约 1.8 秒降到约 0.4 秒（电脑上模拟，真机以实测为准）。

v1.4.2 修复收支和资产分类「迁移并删除」无响应：确认弹窗按钮改用符合微信长度限制的「确认删除」，并提示弹窗调用失败或迁移目标无效。取消或弹窗失败不会删除分类；确认后仍使用原有的迁移和存储保护流程，无需重新导入账本。

增加保险、理财、贷款、旅行、长辈、礼金后，已有账本及旧备份会一次性补齐缺少的支出分类。同名支出分类保留原 ID、图标及历史关联；分类 ID 冲突时使用新的唯一 ID。升级标记随 JSON 备份保存，之后自行删除或改名不会被自动还原。若支出分类接近 40 个上限，只在剩余名额内补齐；未补齐的分类可在整理分类后手动添加。历史金额和预算不受影响，写入失败保留原数据。

优先读取版本 3 主存储键，读取本身不写入任何账本。没有新版使用记录或文件副本时，可以在内存中转换 v2/v1 旧账本，首次主动保存时才写入 v3；旧键保留。v1 账单和分类归为支出并增加收入分类；v1/v2 保留原 ID、金额、退款、日期、备注、预算及时间戳，同时增加默认资产分类、空账户及空金额历史。

主键存在但返回空值、目录读取失败，或已有使用标记/快照/文件副本但主账本缺失时，停止自动创建和保存，并提示检查副本。已损坏的新版数据不会自动退回陈旧旧账本。若升级时发现设备文件备份，也会先要求检查副本，不自行猜测哪个版本最新。

升级写入失败会保留原数据并提示重试。旧副本会额外占用本地存储空间，本版不自动清理。导入前副本与升级前副本使用不同存储键，旧版有效的导入前副本也可以迁移恢复。

## 数据保存与限制

- 数据通过微信本地存储保存在当前设备。换手机、清理小程序数据等情况可能导致本地数据不可用，事先导出 JSON 备份。
- 账单和金额历史按内容切成不可修改的分块（每块不超过约 25 万字符，远低于微信单键 1MB 上限），其余分类、设置和账户资料单独成块。变化的分块先写入新键并回读核验，最后写入主存储键中的小索引作为提交点；中途失败时旧索引和旧分块保持不变，本次新写的分块会被清理。资产金额和历史仍一起提交。核验异常会提示保存结果不确定，避免盲目重复提交。
- 为已有 v3 账本修改数据前，先保护上一份有效数据；保护失败则取消主写入。启动时及成功保存后，更新两个存储快照和两个独立文件副本，保留最近的不同业务版本。仅导出时间变化不淘汰旧业务版本。文件采用先写临时副本并核验、再替换较旧槽位的方式，中断时仍保留另一槽位；遗留临时副本可在检查页查看。
- 主写入已完成、但后续快照或诊断保存失败时，不把本次记账误报为失败；首页和备份页提示保护不足。首次创建账本后也会建立保护，具体结果以页面提示为准。
- 存储快照和导入前副本只保存索引，与主账本共用未变化的分块，只为变化的部分多占空间；不再被任何索引引用的分块在保存后自动清理。设备自动备份文件仍是两份完整账本。保护副本会占用额外空间，存储满时可能提前阻止修改。自动副本和诊断分别固定槽位/最多 40 条，避免无限增长；手动导出的 JSON 不自动清理，可在「导出与备份」中删除。
- 设备文件（两份自动备份和全部手动导出，与微信缓存文件合计最多 200MB）用满时，下一次修改无法先备份上一版账本，保存会被取消并提示删除不需要的导出文件；在此之前的一次保存后，首页和备份页已提示设备文件空间不足。删除导出文件后即可继续保存。详见 [存储保护设计与验收](docs/storage-recovery.md)。
- 数据结构损坏时不自动重置，页面提供副本检查及恢复入口。设备日期回退不会令已经保存的资产历史失效；新增金额记录仍禁止未来日期。
- 微信本地存储总上限为 10MB。按常见的短备注估算约可保存 3.5 万笔（备注越长越少）。已用超过 80% 时首页和「导出与备份」页提示，备份页始终显示当前用量。剩余空间不足约 0.75MB 时暂停新增（账单、账户、分类和金额更新），删除和修改单笔记录仍可保存，这部分空间留给它们改写数据时使用。空间不够时会先释放较旧的一份存储快照（设备自动备份文件仍保留两份完整副本）再重试一次；仍放不下时保存失败并保留原数据，可先导出备份；账户归档保留历史，不释放存储空间。本版不提供云同步或清理历史。
- 当前结构每种收支类型最多校验 40 个分类（合计 80 个）、合计 50,000 笔记录，文件选择上限 16 MB（约可容纳存满 10MB 本地存储时导出的 JSON）。这些是结构/文件校验上限，不代表平台一定能存下对应数量。
- 资产额外支持最多 200 个账户（含归档）、20,000 条金额历史、资产与负债各 40 个分类；这些是数据校验上限，同样受本地实际存储容量限制。
- JSON/CSV 是可读明文文件，包含你的收支、资产和备注。页面隐藏金额不加密导出文件，备份文件请按自己的隐私需要保存。

## 开发检查

在项目根目录运行（需要 Node.js 20.11 或更新版本，推荐 22；测试用到 node:test 的 Date 模拟）。推送到 GitHub 后，每个 PR 和 main 分支都会通过 GitHub Actions 自动运行这两项检查：

```sh
npm test
npm run check
```

若安装了微信开发者工具，可直接使用其附带的编译器检查全部模板与样式：

```sh
node scripts/native-check.js "微信开发者工具安装目录/code/package.nw/node_modules/wcc-exec"
```

`native-check.js` 只使用本地编译器，不启动 GUI、不上传项目。它不能替代模拟器渲染或真机验收。

## 真机验收清单

1. 新增 0.10、0.20 两笔，同一天总计应为 0.30。
2. 补记其他日期，确认日/周/月/年的明细与总额一致。
3. 编辑一笔金额，再登记部分或全部退款，确认列表和统计更新。
4. 新增分类，记账后删除该分类并迁移，确认历史金额不变。
5. 导出 CSV 检查中文、金额与备注；发送 JSON，再选取并恢复，确认账单、分类、预算一致。
6. 取消文件选择及文件发送，确认账本不变；恢复导入前副本，确认数据回退。
7. 关闭并重新进入小程序，确认本地账单仍在。
8. 同月记收入 8,000 元、支出 2,200 元，确认结余 5,800 元；设置预算 3,000 元，剩余应为 800 元，不受收入影响。
9. 在收入视图点击分类、趋势柱子，确认明细只包含对应收入；编辑收入不出现退款项；连续记账保留收入类型。
10. 收入、支出都新增同名分类，确认各自可管理；删除收入分类只允许迁移到其他收入分类。
11. 使用旧版 JSON 恢复，确认原金额、退款、预算不变；再导出新版 JSON，确认恢复后收支均完整。

12. 添加资产 160,000 元与负债 60,000 元，确认净资产 100,000 元；切换筛选不改变顶部合计。记一笔收入或支出后，资产金额保持不变。
13. 修改账户资料不增加金额历史；更新金额（包括同金额不同日期）新增历史。金额归零后可归档、重新启用；有更新历史的账户不能删除。
14. 隐藏金额后检查列表、分类占比、详情和历史，退出重进仍隐藏；主动编辑金额会显示当前金额，保存或取消后恢复隐藏。
15. 导出并恢复 v3 备份，确认资产、负债、更新历史和隐藏设置一致；恢复旧版备份需提示资产清空，取消保持数据，导入前副本可完整找回。
16. 统计切换「全部」，核对跨年收支合计；切换「自定义」，选择跨年的开始和结束日期，核对首尾当天、闰日和无记录年份。分别点击收入/支出合计、分类和趋势柱子，明细的日期、类型、金额应一致；再切回月/年验证前后周期切换。统计不修改账本数据，已导入记录不需要重新导入。
17. 在用 v1.4.x 记过账的设备上升级到 v1.5.0，确认首页、统计和明细与升级前一致；新增、编辑、删除各一笔后关闭重进，数据仍在；「导出与备份」显示本地存储用量，高级恢复中的历史快照和设备自动备份均可检查。
18. 生成三份 JSON 备份，展开历史导出，删除一份后再删除全部历史导出，确认最近一份、账本和高级恢复中的副本不变，显示的时间与本机时间一致；在记账页快速连点「保存」，只记一笔并只返回一页；「我的」页显示当前版本号。
19. 输入 12.、.5 和 1,234.50 各记一笔，确认金额分别为 12.00、0.50 和 1,234.50，列表显示千分位，编辑时输入框为不带分隔符的数字；把手机日期调到最后一次发送备份或第一笔记录 30 天之后，确认首页出现备份提醒，选「7 天后再提醒」后提醒消失。
20. 首页近 30 天超过 100 笔时连续加载更多，确认记录不重复、不遗漏，日期小计不变；统计页点击一根柱子显示区间和金额，再点进入明细；记账页常用分类排在前面；备份页默认只显示常用操作，展开「更多选项」可见历史导出、CSV、高级恢复与诊断。

当前版本不包含云端同步、自动读取微信支付账单、多个账本、收支联动余额、待报销管理和自动识别小票。同一设备上的副本无法防止整个小程序数据环境被删除；所有使用标记和文件一起消失时，也无法仅靠本地信息区分首次使用与历史丢失，请继续保存设备外 JSON 备份。
